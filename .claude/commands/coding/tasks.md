# /tasks - 拆解可执行任务

## 使用方式

```
/tasks {YYYY-MM-DD}-{slug}
```

示例：`/tasks 2026-09-17-rag-tech-qa`

## 执行步骤

1. 在 `docs/superpowers/specs/` 下查找对应的 `-plan.md` 文档（匹配 `{YYYY-MM-DD}-{slug}-plan.md`）
2. 读取技术方案文档，同时读取 `-design.md` 了解需求上下文
3. 按依赖关系拆解为可执行任务，每个任务：
   - 有明确的标题（动词开头：创建/修改/新增）
   - 标注前置依赖（哪些任务必须先完成）
   - 标注涉及的具体文件路径
   - 有验收标准（如何判断完成）
4. 按执行顺序排列

## 输出

将任务列表写入 `plan.md` **同目录**的 `{YYYY-MM-DD}-{slug}-tasks.md`。不得自行创建新目录。

## 任务粒度原则

- 每个任务对应一个可独立验证的交付物
- 纯函数 / service 层任务优先于 handler 与页面层
- 公共封装任务优先于业务组件
- 单个任务预计修改不超过 3 个文件

## 并行分组（Wave）

- 任务按依赖关系分 Wave，同一 Wave 内的任务无互相依赖，可并行执行
- Wave 编号从 1 开始，无前置依赖的任务归入 Wave 1
- 后续 Wave 的任务必须等前置 Wave 全部完成才可执行
- 同一 Wave 内的任务禁止修改相同文件（如有冲突，将其中一个移到下一个 Wave）
- 输出格式示例：

```markdown
### Wave 1
- [任务1] 标题 | 涉及文件: xxx | 验收: xxx
- [任务2] 标题 | 涉及文件: xxx | 验收: xxx

### Wave 2（依赖 Wave 1 的 任务1、任务2）
- [任务3] 标题 | 涉及文件: xxx | 验收: xxx | 依赖: 1, 2

### Wave 3（依赖 Wave 2 的 任务3）
- [任务4] 标题 | 涉及文件: xxx | 验收: xxx | 依赖: 3
```
